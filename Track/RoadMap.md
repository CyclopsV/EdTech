# 🧭 Принципы работы с картой

1. Каждая неделя = один спринт.
2. Не переходи к следующей неделе, пока не выполнены критерии готовности.
3. Все изменения делаются через Git-ветки.
4. Сначала тест → потом реализация.
5. Каждая задача должна быть завершена коммитом.
6. Если возникает проблема — чиним её сразу, не откладываем.
7. Неделя может «переехать» целиком — задачи внутри недели не дробятся между неделями. Если не успел — сдвигаешь весь спринт.
8. В конце каждой недели — 30–60 минут чтения из трека «Под капотом» (раздел в конце карты).

## Неделя 1: Фундамент веб-сервера и инженерная культура

### Цель

Научиться писать чистый веб-сервер на стандартной библиотеке, понять интерфейсы `http.Handler`, `io`, middleware, graceful shutdown. Заложить структуру проекта и инженерные процессы, включая CI.

### Темы для изучения

- `net/http`
- `http.Handler`
- `http.ResponseWriter`
- `http.Request`
- Маршрутизация `http.ServeMux`: паттерны с методами и wildcard (`GET /api/v1/courses/{id}`) — с Go 1.22 весь REST можно делать без стороннего роутера
- Middleware
- `encoding/json`
- `io.Reader`, `io.Writer`
- Graceful shutdown: два механизма — `signal.NotifyContext` (поймать сигнал) и `srv.Shutdown(ctx)` (корректно осушить соединения)
- Структура Go-проекта

### Микрозадачи для понимания (вне проекта)

1. Написать функцию, которая принимает `io.Reader` и считает количество прочитанных байт.
2. Написать простой мидлвар, который оборачивает `http.Handler` и печатает время выполнения запроса.
3. Написать функцию, которая читает JSON из `io.Reader` и декодирует его в структуру.
4. Написать мини-роутер на `ServeMux`, который различает `GET` и `DELETE` на одном пути и извлекает wildcard через `r.PathValue`.

### Реализация в проекте

## Неделя 7: AI-клиент GigaChat

### Цель

Написать свой REST-клиент для AI-провайдера без готового SDK. Освоить OAuth, работу с токенами и ограничениями API.

### Темы для изучения

- GigaChat API: Freemium для физлиц (365 млн токенов на 12 месяцев), модель `GigaChat-2` (Lite)
- OAuth: ключ авторизации как base64 `client_id:client_secret`, scope `GIGACHAT_API_PERS`, токен живёт **30 минут** — нужен потокобезопасный менеджер токенов
- Ограничения Freemium: у физлица один поток генерации → HTTP 429 при параллельном запросе; HTTP 402 — «токены кончились»
- Retry с exponential backoff на 429
- Сертификаты НУЦ Минцифры (установлены до начала недели)
- Паттерн «провайдер за интерфейсом» и ADR

### Микрозадачи для понимания

1. Получить OAuth-токен GigaChat через curl и отправить первое сообщение.
2. Написать потокобезопасный менеджер токена: проверка TTL, обновление через мьютекс без «сваливания в толпу» (подход singleflight на каналах).
3. Написать retry с exponential backoff на 429.

### Реализация в проекте

| Задача | Конкретные файлы и действия |
|--------|-----------------------------|
| Интерфейс провайдера | Создать `internal/ai/provider.go`: интерфейс `ChatCompletion` — с первого дня проектируется под замену реализации (план B: Yandex Cloud, грант 4 000 ₽). |
| Менеджер токенов | Создать `internal/ai/gigachat/token.go`: потокобезопасное обновление OAuth-токена за 30 минут до истечения. |

## Неделя 8: Эмбеддинги, pgvector и RAG

### Цель

Интегрировать векторный поиск и построить RAG поверх своей базы уроков.

### Темы для изучения

3. Включить расширение: `CREATE EXTENSION IF NOT EXISTS vector;`.
